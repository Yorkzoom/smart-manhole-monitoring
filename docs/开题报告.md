## 二、项目背景与意义

### 2.1 现实背景

城市井盖是市政基础设施的重要组成部分，承担着排水、通信、电力等管线的检修入口功能。然而，井盖管理长期面临以下问题：

1. **安全隐患频发**：井盖因车辆碾压、自然老化或人为盗窃而破损、松动、缺失，导致行人跌落事故时有发生
2. **巡检效率低下**：传统巡检依靠人工定期巡查，覆盖范围有限、响应滞后，无法实时发现异常
3. **缺乏数据支撑**：井盖运行状态无历史记录，无法进行趋势分析与预判维护

近年来，国家大力推进"智慧城市"建设，物联网技术在城市基础设施管理中的应用日益广泛。《"十四五"全国城市基础设施建设规划》明确提出推进城市基础设施智能化改造。智能井盖监测系统是智慧城市"地下空间"管理的重要环节。

### 2.2 项目意义

1. **实时监测**：通过多传感器融合，实时采集井盖的倾斜角度、温湿度、气体浓度、光照状态
2. **智能告警**：当检测到井盖异常倾斜、可燃气体泄漏或环境突变时，自动发出告警通知
3. **数据驱动决策**：积累运行数据，支持趋势分析和维护策略制定
4. **低成本可部署**：基于 ESP32 和开源软件栈，单套硬件成本低，具备实际部署价值

## 三、国内外研究现状

### 3.1 国外现状

欧美等发达国家在智慧井盖领域起步较早。英国 Thames Water 公司部署了基于 NB-IoT 的智能井盖监控系统，可实时监测井内水位和有害气体浓度。日本 NTT Docomo 推出了基于 LTE-M 的井盖监测方案，重点应用于下水道管理。韩国首尔市在部分区域部署了基于 LoRa 的井盖倾斜监测网络。

### 3.2 国内现状

国内智慧井盖市场近年来快速发展。华为云 IoTDA 平台提供了设备接入与管理能力，中国移动 OneNET 平台也推出了类似的行业解决方案。海康威视、大华股份等企业推出了集成多种传感器的智能井盖终端产品。高校层面，多所高校开展了基于 NB-IoT、LoRa、WiFi 等通信方式的井盖监测系统研究。

### 3.3 现有方案不足

1. **通信成本高**：NB-IoT/LTE-M 需要 SIM 卡和月租费
2. **系统封闭**：多数商业方案为闭源产品，难以定制化开发
3. **数据本地化弱**：过度依赖云平台，局域网无网络时无法使用
4. **演示门槛高**：需要固定的网关或基站设备

本项目采用 **WiFi + 公共 MQTT 代理** 的通信方案，兼顾演示便利性与技术可行性。

## 四、研究目标与内容

### 4.1 总体目标

设计并搭建一套基于 ESP32 和多种传感器的智能井盖监测原型系统，实现井盖状态的实时采集、无线传输、可视化展示与智能分析。

### 4.2 具体目标

1. 搭建包含 **5 种传感器**（MPU6050、BH1750、DHT11、MQ-2、MQ-4）的硬件采集节点
2. 实现传感器数据的 **WiFi 无线传输**（基于 MQTT 协议）
3. 开发 **Web 仪表盘**，实时展示所有传感器数据
4. 实现 **风险评分算法**，综合评估井盖安全状态
5. 集成 **AI 分析** 功能，提供趋势判断与维护建议
6. 实现 **历史数据持久化与导出**，支持 CSV 下载
7. 提供多设备共享查看能力（独立 HTML 查看器）

### 4.3 技术指标

| 指标项 | 目标值 |
|:-------|:-------|
| 数据采集频率 | ≥ 每 5 秒一次 |
| 数据上传延迟 | < 3 秒（MQTT 端到端）|
| 倾斜角度精度 | ±1° |
| 温度精度 | ±2°C |
| 湿度精度 | ±5% RH |
| 系统运行稳定性 | > 30 分钟无故障 |
| 网页首屏加载 | < 3 秒 |

## 六、可行性分析

### 6.1 技术可行性

1. **硬件成熟度**：ESP32 是广泛使用的物联网芯片，驱动库完善。所选传感器均为市场成熟型号，Arduino 生态有完整的驱动支持
2. **通信方案**：MQTT 是物联网领域标准协议，公共 Broker 服务稳定可靠
3. **开发栈成熟**：Node.js + React 是当前最流行的 Web 开发组合之一，社区资源丰富
4. **AI 集成**：DeepSeek 提供标准 OpenAI 兼容 API，调用门槛低
5. **风险可控**：各模块存在备选方案（HTTP POST / 华为云 MQTT / 本地诊断），可降级运行

### 6.2 经济可行性

1. **硬件成本低**：全套硬件约 **84 元**，远低于商用智能井盖终端
2. **软件零成本**：所有软件均为开源或免费层级
3. **运行成本低**：公共 MQTT Broker 免费，DeepSeek API 免费额度充足

### 6.3 时间可行性

项目开发周期为 **3 天**，按以下阶段执行：

| 阶段 | 时间 | 内容 |
|:-----|:-----|:------|
| 硬件搭建 | Day 1 | 面包板接线、单传感器验证 |
| 固件开发 | Day 1-2 | 传感器读取、WiFi、MQTT 发布 |
| 后端开发 | Day 2 | Express 服务器、MQTT 桥接、Socket.IO |
| 前端开发 | Day 2-3 | React 仪表盘、ECharts、地图 |
| 集成测试 | Day 3 | 全链路联调、Bug 修复 |
| 文档整理 | Day 3 | 项目文档、开题报告 |
